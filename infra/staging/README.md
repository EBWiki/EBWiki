# Staging host OpenTofu (`ebwiki.staging.grandkru.com`)

OpenTofu stack for [GKT-462](https://linear.app/gkt/issue/GKT-462). Adopts the existing Railway **ebwiki** project and service, points **`ebwiki.staging.grandkru.com`** at Railway (Grand Kru standard: `<site>.staging.grandkru.com`), and wires runtime **`DOPPLER_TOKEN`** on Railway. **`HOST`** in Doppler **`stg`** matches **`staging_hostname`**.

**PR Manager** runs **`make plan`** and **`make apply`** on the PR Manager machine. **`scripts/staging-plan.sh`** and **`scripts/staging-apply.sh`** load **`ebwiki/infra`** via **`doppler run`**. Bootstrap ( **`make bootstrap`** ) must have run first using **`grandkru/prd`** makers; see **`infra/bootstrap/README.md`**.

**Legacy URL:** **`staging.ebwiki.org`** stays a proxied CNAME to the suspended Render origin (content not changed by OpenTofu). A Cloudflare **Single Redirect** ruleset sends **`staging.ebwiki.org`** to **`https://ebwiki.staging.grandkru.com`** with path and query preserved. Rollback: disable or remove the ruleset; the Render CNAME remains.

**Follow-up:** PR #4528 **`/health`** Access lock must include **`ebwiki.staging.grandkru.com`** ( **`infra/cloudflare/`** after staging apply).

## Prerequisites in ebwiki/infra

After bootstrap, **`infra`** holds minted Cloudflare DNS tokens (not the token maker), R2 credentials, **`RAILWAY_TOKEN`**, **`DOPPLER_TOKEN`** for apply, passphrases, and staging username / Postgres DB name seeds.

## Remaining manual steps

1. **Railway GitHub app** (browser) or **`scripts/railway-github-access.sh`**.
2. **Railway CLI** and **SSH key** registered with Railway on the PR Manager machine for **`railway ssh`** snapshots.

OpenTofu creates **`STAGING_PASSWORD`** in **`stg`** at apply time.

**`terraform.tfvars`** is generated by **`scripts/write-staging-tfvars.sh`** before plan/apply. That script stops if **ebwiki.org** already has Single Redirect rules in Cloudflare (only one entry-point ruleset per phase). If redirects already exist, import the ruleset and copy its rules into **`cloudflare.tf`** before applying; do not create a second ruleset.

## Cloudflare providers

Staging does **not** use **`CLOUDFLARE_TOKEN_MAKER`**. It uses **minted** tokens from bootstrap:

| Alias | Secret in **`infra`** | Zone |
| --- | --- | --- |
| **`cloudflare.ebwiki`** | **`TF_VAR_cloudflare_dns_api_token`** | **ebwiki.org** (legacy record + redirect) |
| **`cloudflare.grandkru`** | **`TF_VAR_cloudflare_grandkru_dns_api_token`** | **grandkru.com** (staging CNAME + Railway verify TXT) |

Those tokens were created by bootstrap **`cloudflare.token_maker`** with DNS and Dynamic URL Redirect permissions on ebwiki only.

## Behavior change

Live staging runs image **`ebwiki/ebwiki:184`** with **`db:prepare`**. Apply switches to **main** with **`railway.staging.toml`**. **`scripts/staging-apply.sh`** snapshots Postgres before apply.

## Commands

PR Manager, from the repo root:

```bash
make plan
make snapshot   # optional; staging-apply.sh snapshots first
make apply
```

Plan and apply run on the PR Manager machine (not in PR CI).
